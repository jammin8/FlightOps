# POC1 primary/owner composition: offline source component

This new six-path component composes supplied capture snapshots, exact-run lookup results and caller-protocol records into a descriptive one-to-many graph. It does not read sources, run SQL/processes/network, call ports, publish files, register a CLI, mint a capability or emit normalized model/kernel rows.

## Problem and result

The guarded dispatch recorder retains a call's exact intent/dispatch identity, but its singular owner wire cannot represent all attempts/turns and cannot resurrect a historical opaque handle. The fixed CI host lookup supplies bounded descriptive candidates, not authenticated assignment/usage facts. POC1 preserves those original inputs and links their exact scopes without altering either frozen contract. A separate pure validator checks consistency of the supplied two-host caller protocol. Consistency is not proof the calls happened.

The new contracts are flightops-primary-owner-input/1, flightops-primary-owner-call/1 and flightops-primary-owner-composition/1. Input/call/output all contain closed constants authentication:not-performed, merge_authority:false and normalized_rows:[]. The extra three input/call constants implement the explicit task requirement that serialized inputs/outputs stay unverified; the design's five input data fields remain unchanged. There is no qualified/primary enum or boolean. Supplied hashes, nonces, labels, role strings and clean source commits cannot change that state.

Public functions are primary_owner_contract.accept_input(value,check=...), accept_output(value,check=...), primary_owner_composition.validate_protocol(value,check=...) and compose(value,check=...). Input can be decoded mappings or JSON bytes. Functions are complete pure computations for their declared domain. Import and function execution have no file/process/SQL/network/native/capability side effects. Callback cancellation remains fatal; ordinary callback exceptions become CompositionCancelled rather than a recoverable contract refusal. Existing fatal BaseException instances propagate unchanged. Frozen validators remain unmodified.

## Closed fields and references

Input contains schema, primary_snapshots, lookup_observations, caller_transcripts, composed_at and the three fixed unverified constants. Arrays each have at most8 occurrences. The entire packet has at most100 capture-event occurrences and100 retained lookup-row occurrences, including copies. Canonical input and output must each fit1MiB. Excess is rejected, never truncated. JSON is bounded at depth32 before decoding; duplicate decoded keys, unknown fields, invalid types, bool-as-int, nonfinite/overflow and private/freeform fields reject. The original decoded values, list occurrence order, copies, nulls, source clocks, candidates, conflicts and gaps remain exactly in output.input; JSON whitespace/object key insertion order is not an evidence field.

Capture events/snapshot/manifest schemas are copied from the actual frozen definitions and validated through LedgerSnapshot.fields. Lookup envelopes are validated through the unchanged accept_result recomputation. POC1 does not accept caller-provided normalized projections or alter their schema globals. Schema documents in the external author packet are generated directly from the actual new definitions, with closed expansion for nested event unions, snapshots and lookup envelopes.

Composite assignment key is recorder_id+recorder_epoch+assignment_id. Event references contain snapshot_digest,event_id,event_digest. A lookup reference contains selection_id,digest. Digests use the existing canonical encode format, including its final newline. Graph references are content-based, not array indexes. Exact envelope copies increase occurrence denominators without changing canonical graph references. Conflicting content with the same immutable event/selection/invocation identity remains retained and taints the affected identity/dependents; no latest/earliest winner is selected.

Caller request/result reference is closed:kind(event|selector|lookup),digest,recorder_id,recorder_epoch,assignment_id,event_id,selection_id. Event digest names one exact scoped event and selection_id is null. Selector digest names the entire original selector; event_id names its dispatch_event_id. Lookup digest names the entire validated lookup envelope. The complete scope and digest must agree, not merely a nearby event ID or run. No reference authenticates origin.

Caller fields are schema,producer_version,invocation_id,parent_invocation_id,stage,host,route,request_ref,result_ref,request_nonce,result_nonce,elapsed_ms,started_at,observed_at,terminal,exit_code,source_bindings,outcome,failure_code plus the three fixed unverified constants. Unknown result/nonce/observation/exit/parent values remain nullable where defined. Producer version for this declared protocol is flightops-primary-owner-protocol/1; it is not a deployed runtime claim.

Each source binding has component,version,digest,before_identity,after_identity. Identities contain only module,device,inode,bytes. Components are capture,guarded-orch,owner-lookup. Their supported declared versions are flightops-boundary-event/1,flightops-guarded-orch-call/1,flightops-owner-lookup-source/1 respectively. Before/after identities must agree; contradictory binding copies refuse. Lookup bindings must match every supplied lookup code lease's module/identity/digest, with no missing/duplicate module. Dispatch snapshots contain no measured code leases, so dispatch binding hashes can only be checked for internal consistency/version/equality, not independently anchored to executing code. This limitation never becomes source authority.

Fixed failure_code values are timeout,cancelled,transport,malformed-response,source-changed,publication-ambiguous,unavailable. They describe supplied caller failure, not an exception body or command result. Version/route/host/terminal/ref/source/nonce/clock mismatches produce scoped protocol refusal rows with original records retained. No private message, argv,cwd,stdout/stderr,auth or task prose is a field.

## Graph and lifecycle semantics

Assignments retain all intent/dispatch event references, lookup references, relation references and lifecycle dispositions. Decision state is explicit-unverified or unknown. Input/result/reviewed heads, memberships, replacement knownness and all dispatch/worker/result/decision/source clocks remain inside original unchanged events. Transport completed is not a worker or review decision. Missing decision/actor/protocol/project facts stay unknown. A primary snapshot has no typed authenticated project field: local/flightops is not a project or PR attestation.

Linking checks exact recorder/epoch/assignment/dispatch kind+ID, returned thread+run, original dispatch response clock and lookup thread-row project relation. Requested owner references must bind the exact scoped owner event and its candidate payload; wrong kind/assignment/epoch/payload cannot borrow another mapping. Every candidate, including null-turn/mismatched/conflicting ones, is retained as an edge or a null-candidate unresolved edge. Raw candidate references name the complete input lookup and candidate digest; source row references remain original lookup references. Relation state is structurally-matched,unresolved or conflict, and attribution_state is always unallocated.

All valid attempts/turns stay a set. Multiple candidates do not force an exclusive owner or erase independently supported individual edges. Same run/thread/project across assignments yields separate potential membership edges and a shared-run-membership-unallocated reason; no duplicate cost, selected role, equal usage split or winner. Unknown lookup retention/children/global inventory and table/cap gaps remain visible. Lookup selected_candidate_id never supplies authority.

Revision>0 without explicit predecessor withholds lifecycle completeness, while an exact independent lookup relation can remain structurally matched. Predecessor/task/repository/PR/input/review target/revision/time relationships are checked independently for every successor. Dependency cycles, missing parents, contradictory terminal copies and unresolved review triggers propagate only to affected dependent lifecycle scopes. Review-triggered rework must bind the review's task/repository/PR and reviewed head as its INPUT, with an explicit prior changes_requested decision. RESULT heads may differ and remain raw. CI triggers have no CI receipt collection in this contract and therefore remain unresolved rather than being inferred from task text. Actor independence remains unproven even when an explicit supplied decision is internally consistent.

Represented manifest/segments are checked for epoch, sequence/previous-event digest, segment digest/count/range/chain and manifest terminal digest/clock. Segment bytes are the frozen ledger's canonical encoded event lines. Missing/gapped snapshots remain visible, not globally complete. Concrete represented epoch/digest contradictions taint the affected snapshot identities; other missing-history gaps keep lifecycle incomplete without automatically erasing exact individual content relationships. A manifest-only empty stream remains in the stream denominator. This is validation of represented semantics, not proof the original on-disk directory existed or was exhaustive.

Canonical derived arrays are independent of outer snapshot/lookup/call ordering and identical envelope copies. Event order inside a represented segment is semantic and is not silently rearranged to repair its chain. Distinct conflicting events/dispatch records count as distinct content observations; logical assignment keys and lookup selections have separate counts. Original input order/copies remain in input and affect its digest as expected.

## Supplied caller protocol

Allowed stage/host/route and maximum elapsed_ms are fixed in code:

| Stage | Host | Route | Budget |
| --- | --- | --- | --- |
| dispatch | root-mac | guarded-orch |5000ms |
| lookup | root-mac | existing-ssh-owner |15000ms |
| lookup | rig | existing-ssh-owner |5000ms |

No caller budget is accepted. Dispatch has no parent and references its exact intent/result event pair. A Root lookup has that exact dispatch call as parent and exact selector/lookup references. One CI host observer call has that Root lookup as parent, matching references and nonce. Root SSH and CI host observer have distinct invocation IDs but may share the same correlation nonce because they are one logical lookup chain. Nonce reuse across unrelated calls, a second logical Root lookup, duplicate CI host calls, conflicting invocation copies or swapped source/result references refuse. A refused/missing CI host child refuses its Root chain; refused parents invalidate dependent calls. Independent dispatch/call scopes survive.

Completed means terminal completed+exit0+persisted+no failure_code and a bound result, not merely a successful-looking payload. Null/failed/unknown exit, malformed/changed/ambiguous/cancelled result and source mismatch remain refusals. Exact matching nonce is supplied request/result correlation, not a server-echo or authentication assertion. Caller observed_at must not precede its own started_at. Root dispatch/request/response ordering and original selector response equality are checked. Worker run start after dispatch response is valid asynchronous work. CI host acquisition/observer clocks are checked only in that CI host context; unsynchronized CI host and Root wall clocks are not treated as one process duration or a coverage refresh.

## Remaining source and runtime boundaries


NEW FULL independent whole-six-path review of the immutable candidate is required. The separate future two-host source-owned producer/courier is not implemented. Existing Darwin GuardedOrchPort and the fixed CI host lookup's empty-success-stdout transport gap remain unchanged. A future reviewed runtime must own durable intent before one necessary dispatch, hold its original live context across a fixed SSH lookup, own one CI host CLI/result response, retain exact return/source custody and close ambiguously without retry on loss. A capability, if later designed, must stay in-process and nonserializable; no imported file/hash/nonce/Root boolean can recreate it. Historical handles/epochs/ledgers are not resumed.

Real caller terminal and ordinary Git creation/publication witnesses, authoritative roles/actors/decisions, native-applied setup/usage, exact PR membership/CI/policy, allocation/children/retention/coverage, normalized source-aware consumers and eventual UI/native installation remain separate work. Frozen20PR support/70%common support/90%coverage-or-bounds/precision/calibration/multiplicity/unknown denominators remain unchanged. No90-calendar wait, fake comparison job, forced winner, population relabel, workflow activation, source capture or Mac installation follows. Freeze and PARK after this packet.
