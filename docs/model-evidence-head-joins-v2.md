# V2 head and assignment bridge, source-only

This separate pure component represents observations that the frozen v1 head/assignment contract cannot express. Unknown replacement remains null. Intent, dispatch, native owner, worker result, explicit work/review decision and observation clocks remain separate. Input/result/review heads and original versus later result PRs are distinct. No existing loader, CLI, schema, recorder, port, kernel, Swift reader or feed adopts v2 automatically.


## Interfaces

join_contract_v2 defines evidence-head-input/2 and evidence-head-joins/2, closed validators and matching JSON Schema documents. Input has an explicit synthetic/supplied origin, generated_at, optional original agent-evidence/1 or /2, existing strict source/HEAD/CI/policy observations, selected-CI raw typed inputs and raw flightops-boundary-snapshot/1 selections. Every input field is required; genuine absence uses null or an empty selected collection. Empty selection is not complete inventory. Extra projection/authentication/qualified flags are refused. Labels and hashes do not authenticate supplied facts.

HEAD extends a deep copy of v1 HEAD with nullable replaced and explicit predecessor_revision. A higher revision requires its exact prior revision; repository/PR/full SHA remain immutable for that ID. All unique original observations survive under output.input, including superseded/conflicting candidates and original clocks. Replacement state is current/replaced/unknown/conflict; known_current is null for unknown/conflict. Unknown is never converted to false or treated as current. Conflicting scopes withhold that identity and retain unrelated heads.

accept_input accepts an explicit object or bounded UTF-8 JSON bytes. Duplicate decoded keys, nonfinite/overflow values, bool-as-int, excessive depth/bytes/counts, wrong types, unknown keys and private extra payloads fail closed. Agent originals must exactly equal the frozen accepted envelope; this bridge refuses silent sanitation/health rewriting. Raw snapshot validation uses the frozen event/manifest contract and recomputes projection from events, never from a supplied projection. Supplied snapshots preserve their manifest/gaps/as_of and source times. Hashes pin structural content, not source authority or complete ledger custody.

The aggregate input and output bounds are4MiB each, JSON depth32, up to5000 rows per collection,128 explicit HEAD/CI sources,32 boundary selections and8 selected-CI captures. Frozen event16KiB and replay5000-event/4MiB bounds also apply. Aggregated boundary events must fit the frozen projector bound. Output duplication of original observations can reach the output cap before the input cap; it rejects explicitly instead of truncating inventory. Cancellation checks run at validation and derivation boundaries and in dependency loops; fatal cancellation is not a record-local parse error. Imports open no files/network/process/database and no function discovers source/default output paths.

joins_v2.derive recomputes a deterministic canonical projection. Exact copies are idempotent; permutations of observation collections/events do not change output. Different copies are retained, not latest-wins. Original agent arrays/settings/buckets/ownership/reconciliation/retention and source clocks remain unchanged. Exact repository/full-SHA/PR matching only creates descriptive target IDs; it does not prove role, producer, publisher, operation or usage allocation.

normalize_pr_record consumes the existing derived PR-record shape and emits one v2 HEAD per selected head. It never substitutes false to call the old normalizer. from_selected_ci invokes the frozen strict pure normalizer and retains its raw typed observations as selected_ci_inputs, plus its CI/policy observations. It adds an explicitly unknown-replacement head with unknown readiness/history/policy applicability. Current status, run number, later policy or summary booleans cannot manufacture historical attempts or first-ready. No source file/feed is read implicitly.

from_v1 explicitly imports a strict v1 head/CI selection only when the original agent is already exact and operation/assignment collections are empty. Nonempty v1 receipts require their original boundaries; the helper refuses them rather than guessing original intent/result clocks or dropping them. This is a narrow compatibility helper, not a general v1 migration.

## Assignment and operation semantics

Assignments expose all selected intents/dispatches/owners/resolutions, original intent_at, independent nullable input repository/PR, explicit result repository/PR, input_sha/result_sha/reviewed_sha, actor, native owner and decision. Missing intent still leaves a selected dangling identity with nullable facts. Native binding is recomputed with the frozen exact thread/task/run/attempt/session/turn relation; requested owner references must belong to that assignment. A known typed decision can remain independently visible with absent native owner/actor/PR. It remains an unverified observation. Transport completed status alone never supplies a decision or worker completion.

The V2-1 repair clears the selected owner whenever requested-binding identity, kind, assignment scope or payload validation fails. Raw owners/events and the original requested ID remain intact, while known.native_owner and native_owner_mappings no longer count that rejected mapping. A matching or genuinely unrequested owner remains selectable; absent owner alone does not erase an independent descriptive decision. The V2-2 repair marks a nonzero intent revision without its explicit predecessor unresolved before selecting a complete decision. It retains the intent/resolutions/inventory and original clocks; dependent review/rework lifecycles inherit unresolved dependency, while unrelated assignments remain independent. Revision0 without a predecessor and valid linked revision1 successors retain their existing behavior. Neither repair changes a wire/schema or source-authority convention.

Contradictory intent/event/dispatch/native/actor/terminal facts invalidate only the affected lifecycle. Source epochs cannot be combined into one unambiguous assignment by line/time proximity. Dispatch before durable intent, malformed worker intervals, observation before worker completion, inconsistent result/decision clocks, mismatched target/owner and missing explicit review outcome remain conservative. Open-to-terminal resolution revisions require an explicit same-assignment predecessor event; contradictory old terminal copies cannot be overwritten by a higher revision.

Rework's explicit review trigger binds task, repository, PR and INPUT SHA to the actual reviewed SHA and prior changes-requested decision, with temporal order. Its RESULT SHA may differ. CI triggers require exact stable captured check/attempt/history binding and an explicit target; missing attempts stay unresolved. Every successor independently validates its predecessor/task/target/revision/time relation. A valid successor cannot authorize a wrong-task successor through shared predecessor membership. Cycles, dangling dependencies and unqualified parents propagate only to dependent identities. Same declared actor review is excluded; absence of a known distinct actor relationship remains unavailable rather than inferred independence. Actor labels still do not authenticate source or prove production.

Operations retain every typed event, the frozen recomputed invocation terminal, owned-process knownness and all Git observations/dispositions. A final invocation/API response does not manufacture a PID, native owner or owned process. Git observations remain unqualified even with a coherent lifecycle. This packet adds no executor, witness authority or normalized operation proof.

CI/policy calculations reuse frozen deduplication and scoped history checks without mutating module globals. Invalid intervals stay in original input, get an explicit invalid-interval disposition and invalidate only their job history. Conflicted histories cannot disappear and turn a later pass into a first pass. Unrelated scopes remain usable descriptively. Frozen CI policy/statistical meanings are not changed or granted merge authority.

## V1 compatibility and denominators

The separate compatibility object contains a strict v1 input only when agent-evidence/2 and representable facts permit it. Unknown replacement/conflicting heads are listed as omitted IDs with dispositions while remaining in the full v2 input and denominators. Invalid/conflicting CI history cannot become a healthy v1 head by dropping a check. A representable assignment must have the exact native/agent/actor/PR/head relation, original single-head semantics and original intent/result-observation times within the worker lifetime. Missing owner/PR, different input/result heads, cancellation or observations outside that lifetime produce explicit nonrepresentability reasons. No source clock is stretched or renamed to force v1. Conversion never emits operation proofs.

Selected heads/PR identities/head observations, replacement unknown/conflict, selected events/assignments/operations, explicit decisions, native mappings and owned-process unknowns have separate denominators. Agent selected run/turn inventory remains separate from accepted turns, captured responses, known bucket observations and reconciled main turns. Child/retention/eligible-inventory gaps remain explicit. Shared memberships stay selected with allocation unknown. There are no authenticated normalized rows or proven exact PR-linked usage in this unqualified input family; zero such proof rows means unattributed, not zero work or complete coverage.

Every output has authentication not-performed, merge_authority false and normalized_rows empty. accept_output recomputes the result from its validated original input and rejects tampered projections/denominators. Successful representation does not establish source authority, CI merge permission, a cohort, calibration/support/precision/multiplicity exception, a winner, Best/Needs attention, runtime feed or app installation.

A verified opening receipt claimed by more than one PR or head in a repository makes every claimant ineligible for verified R0 CI, with `r0-receipt-conflict`, as v1 does. The check reads every retained head row, so a claim in an older revision still counts.
