# Typed boundary capture, source-only

The capture modules record typed work decisions, dispatch/execution observations and explicit missing facts in an inert ledger. They have no built-in Orch/provider client, Git mutator, subprocess executor, live reader, feed, hook or service. This packet implements ports and deterministic synthetic adapters; it does not attach them to current work. The frozen agent-evidence/2, join contracts, native/acquisition code and statistical policy are unchanged.

## Interfaces and source authority

`capture_contract` defines closed `flightops-boundary-event/1` tagged payloads and `flightops-boundary-ledger/1` manifests. AssignmentIntent, DispatchObservation, OwnerBindingObservation, ExecutionStart, ExecutionResult, GitResult, AssignmentResolution and CoverageCheckpoint are validated dataclasses. CaptureDisposition and LedgerSnapshot validate narrow output structures. Unknown keys, duplicate decoded JSON keys, unsupported tags, bool-as-int, NaN, oversized/nonfinite numbers, invalid IDs, invalid refs and excessive resources reject with fixed categories. UTC clocks are numeric seconds; original source clocks can remain null. Recorded observation time is separate from original start/completion/decision times. Monotonic time is only a local regression guard and is never serialized as UTC.

Limits are event16KiB, append64KiB, selected event replay4MiB/5000 events, segment4MiB, parents8, references/dependencies64 and JSON nesting32. These limits belong only to this new inert module. Output and manifest files are also bounded at4MiB; a wrapper that would exceed its output cap is rejected, not silently truncated. Byte accounting stops while validating event selections/append batches. No acquisition limit is changed.

Construct Ledger with an explicit absolute output directory and explicit recorder ID/epoch, then call `create()` for a new empty directory. Construct BoundaryRecorder with that ledger, an explicit BoundaryPort implementation and explicit clocks when needed. Registration is Python integration code, never a JSON field. A supplied dictionary cannot register a port or reconstruct an assignment/invocation handle. Importing these modules opens no application file, process, database or network connection and discovers no default path.

`prepare_assignment(intent)` durably writes the typed decision before returning an opaque pending handle. `dispatch(handle)` consumes its single dispatch attempt and calls the registered port once. The descriptor contains only target thread ID and a recorder-issued client request ID. The port must wrap the existing authorized guarded `orch_thread_send` path; this code has no message/prose argument, delegate_task migration, alternate provider or polling route. The private task instruction stays in the actual caller's existing transport code and must never enter this library.

FixturePort only returns typed synthetic observations. BoundaryPort has no default transport implementation or filesystem/DB/native fallback. A missing port or failed result remains a fixed unavailable category with the durable intent pending. After any action attempt, a receipt append failure or interruption never repeats that action. Handles are local to their recorder instance; imported/replayed IDs cannot resume an old dispatch. A new explicit assignment is a new caller decision, not an automatic retry.

`observe_dispatch`, `observe_owner_binding`, `observe_execution`, `observe_git_result` and `resolve_assignment` require a receipt from the registered port bound to the exact local handle and typed record class. These checks guard accidental API misuse. They do not authenticate arbitrary code executing in the same process/account. A caller can write false metadata, copy a digest or modify a file; no same-account adversarial authentication is claimed. An actual observer route must be separately qualified against its real call/response custody.

All disk replay and `import_supplied` output has custody `supplied-replay`, authentication `not-performed`, merge_authority false and `normalized_rows=[]`. Recorder-created files, caller labels, hashes, opaque UUIDs, directory ownership and successful schema validation never turn replay into a qualified live observation. No JSON authority switch exists. Field knownness means that the selected typed observation supplies a value; it does not authenticate its truth. Actor labels never establish independent review.

## Assignment, owner and result semantics

Intent records explicit role/category/task/repository/target, optional PR/head/replacement state, memberships, trigger and predecessor. No role is inferred from a title or task text. The selected facts retain unknown replacement as null, including a head observation and named v1 bridge unavailability. It never becomes false or disappears from inventory. Multiple PR memberships remain shared with unknown allocation; this module has no usage allocation or token bucket path.

Dispatch observations preserve the guarded route's delivery/status, message/thread/task/run IDs and original request/response clocks. The current tool declaration requires a runId; the new contract can also retain an unavailable/pending run as null without claiming that null is a qualified current-tool return. A later owner mapping needs matching thread and every known transport task/run identity. The original attempt's runId, turn's runAttemptId and session identity must agree, with sanitized original source references. An unknown native/provider dimension is not filled from current thread configuration. The codex run key is scoped to the matched attempt; original orchestration run stays separate. Requested owner-binding references must resolve exactly or remain unknown.

A completed worker is separate from a typed implementation/review decision. Review completion requires the explicit reviewed SHA and accepted/changes_requested outcome. Natural dispatch-before-worker and decision-observed-after-worker clocks are preserved and reported as v1 representation limits. Rework input and result heads may differ; no clock or SHA is changed to fit the frozen assignment contract. A result may supply a later PR target while the original intent PR stays null. Wrong known result repository/PR is a conflict.

Equal copies preserve history without creating work. Contradictory event IDs, assignment intents, owners, terminal decisions or operation results taint affected identities. Explicit resolution revisions need predecessor event linkage; earlier terminal contradictions cannot be overwritten by a later pass. A successor is checked independently against predecessor/task/repository/PR/input/review target and temporal order. A valid successor cannot authorize an unrelated successor through shared predecessor membership. Retargeting observations that cannot meet those checks remain retained/unresolved. Dangling/cyclic event dependencies and assignment triggers/supersession are explicit. Rework from review requires a consistent explicit changes-requested decision on the input target; CI-trigger qualification remains unavailable without a typed CI-attempt source boundary.

## Execution and Git observations

`begin_operation` accepts a closed ExecutionStart descriptor, creates an opaque operation/invocation handle and appends the start. It accepts no command, argv, cwd, output or private-body digest. FixturePort's ExecReply models metadata only: unified-exec continuation session, final exit/signal, optional original source time/native completion ID and sanitized references. A session without terminal exit remains in progress. A final continuation is bound to the handle's own session. Immediate exit without PID/session is an invocation result with process identity unknown. Startup acknowledgements and protocol switches remain unknown; exit0 in a startup shape is insufficient. Typed terminal/clock/process contradictions preserve all observations and withhold the affected terminal state. Different source epochs cannot be ordered into a single operation lifecycle by unrelated line order.

GitResult is an observation validator, not an operation adapter. It checks canonical repository binding, full object IDs, intended tree/ordered parents and before/result relation, destination/ref/result, dry-run, pre-existing object, no-op and partial/unsupported outcomes. Publication is separate from object construction and concurrent destination-before mismatch is explicit. Even a consistent synthetic shape retains `git-observation-unverified`; it is not production/publication proof. No commit-tree engine, normal commit/push executor, shell parser or output-body miner exists here. The source packet's own ordinary Git commit is not fed through this fixture adapter or claimed as a model producer receipt.

## Ledger custody and failure behavior

One nonblocking POSIX writer lock protects each explicit ledger directory. No live lock is stolen. A durable immutable identity marker distinguishes an initialized epoch even if its manifest is deleted. Existing unrelated directories are rejected before creating a writer lock. The manifest atomically pins immutable content-addressed transaction segments, each at most the append cap; segment rotation occurs on each transaction rather than rewriting a mutable tail. Files and directory entries are fsynced before the next publication boundary.

Readers pin a manifest and bounded segment set, check regular-file/stable inode/size/clock metadata and digests, and reject symlinks, hard links, traversal or nonregular file access. Invalid/torn records are excluded without echoing/hashing private values; valid neighboring typed observations survive with completeness invalidated. Missing/deleted segments, sequence/epoch/digest/count/range gaps, unknown directory entries and advancing manifests are explicit. A missing manifest is unavailable, not a healthy zero. Orphan segment/temp entries after interruption retain a partial state and block further appends; this packet does not silently repair/truncate or redispatch.

Same canonical event bytes are idempotent. Conflicting same-ID copies require new valid chain positions and are retained for identity-scoped conflict projection; a malformed chain cannot silently replace old source history. Each event includes sequence, previous digest, recorder epoch and original observation clocks. Reading/sealing later does not move as_of to the read clock. A successful seal uses an explicit immutable output file outside the ledger directory. Existing unequal output is not overwritten, and failed/cancelled validation preserves last-good bytes. Cancellation propagates as a dedicated fatal class; the CLI returns130. Publication already committed before cancellation cannot be undone; its outcome must be checked by readback, never by retrying an external action.

Coverage checkpoints describe only selected recorder sequences. Sequence holes, pending identities, unavailable inventory, child/retention/shared-allocation facts remain in gaps and denominators. Even a contiguous ledger does not prove all-eligible-task/fleet coverage, native retention, whole-task usage, a prospective comparison window or90-day history. No complete-through source watermark or winner is invented.
