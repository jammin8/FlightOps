## Bounds, custody and publication

One shared monotonic5-second budget covers source leases, transaction, derivation and publication checks. At most100 total retained rows across all tables; a cap+1 fetched row sets rows_seen101/truncated and is not retained as an admitted record. Unread tables/invalid rows remain explicit; partial uniqueness cannot pass. The complete sanitized result/input contract is bounded at1MiB. Large malformed payloads are rejected in SQL before JSON extraction and never copied into Python. No budget/row/native/byte widening is configurable. Pure memory loops and SQLite progress callbacks propagate dedicated fatal LookupCancelled; callback bodies are never printed. Standard OS/SQLite/syscall execution is not a hard real-time or hostile-code sandbox; late results are refused before acceptance/publication where still possible.

The source entry holds FDs for the three owner modules and their contract/schema dependencies. It hashes only these code files and sanitized rows, checks code path/held-FD device/inode/size/mtime/ctime across the read and before replace, and emits safe module names/leases. This observes inspected source bytes, not a cryptographic execution chain. Imports/loaded bytecode, Python/SQLite/stdlib, caller/startup dependencies and malicious same-account replacement remain trust limits; lease hashes never self-authenticate imported files.

DB before/after path identity uses device/inode only. Symlink paths and replacements fail; legitimate WAL writer size/mtime changes are not corruption. There is no DB hash/mtime freshness claim or claim to own SQLite's internal FD. The read transaction supplies SQLite's logical snapshot consistency, not source authenticity or historical retention. Exact as_of is retained, later source values stay marked outside selection, and complete_through remains null.

Publication is an explicit independent /tmp sidecar, not a ledger append/feed. Existing output must be a valid matching-selector sidecar; symlinks/hardlinks/escapes and conflicting existing files refuse. Cooperative writers lock the destination directory without retries. A bounded fsynced temp file, stable prior readback and atomic replace protect complete bytes. Failures before replace preserve last-good bytes; cancellation/error after replacement or during final cleanup can mean publication already committed. The caller must inspect the destination and park, never retry the lookup automatically. Same-account noncooperating writers and filesystem durability guarantees are outside the claim. No historical Mac handle is reconstructed and no old epoch is extended.
